# Fixed-64 ChaCha20-Poly1305 RTL baseline

This package is the functional RTL baseline for the ZedBoard project protocol.
It matches the deterministic values generated by `golden_reference.c`.

## Modules

- `rtl/chacha20_block.sv`: one RFC 8439 ChaCha20 64-byte block, 20 rounds.
- `rtl/poly1305_fixed96.sv`: Poly1305 over the project's fixed 96-byte MAC input.
- `rtl/aead_fixed64_wrapper.sv`: counter 0 key derivation, counter 1 encryption,
  and Poly1305 control.
- `rtl/aead_fixed64_decrypt_wrapper.sv`: authenticate-first decryption with
  fail-closed plaintext output.
- `rtl/aead_fixed64_engine.sv`: shared encrypt/decrypt engine using one
  ChaCha20 core and one Poly1305 core.
- `rtl/aead_arbiter_4session.sv`: four-session context table, round-robin
  request selection, nonce/AAD construction, counters, and replay rejection.
- `rtl/aead_session_manager_bram.sv`: parameterized 64-session BRAM table,
  indexed request handling, counters, replay rejection and shared AEAD engine.
- `rtl/aead_traffic_indexed_axi_lite_frontend.sv`: one PS-scheduled AXI
  request channel with a 6-bit session slot.
- `rtl/aead_axi_lite_wrapper.sv`: 32-bit AXI4-Lite PS interface with no DMA
  and no request FIFO.
- `rtl/keccak_f1600.sv`, `rtl/sha3_shake_stream.sv`: common SHA3-256,
  SHA3-512, SHAKE128 and SHAKE256 engine.

  kernel with coefficient banks.
- `rtl/mlkem512_codec_primitives.sv`, `rtl/mlkem512_sampling_primitives.sv`:

  Decaps BRAM subsystem and internal bridge to the polynomial accelerator.
- `rtl/mlkem512_unpack_controller.sv`,
  `rtl/mlkem512_kpke_decrypt_engine.sv`: ciphertext/secret-key unpack and the

  SHAKE-based matrix and CBD noise polynomial generation.

## Fixed protocol

```text
AEAD input
  key        32 bytes
  nonce      12 bytes
  AAD        16 bytes
  plaintext  64 bytes (message followed by zero padding)

AEAD output packet
  AAD         16 bytes
  ciphertext  64 bytes
  tag         16 bytes
```

Poly1305 authenticates exactly six 16-byte blocks:

```text
AAD[16] || ciphertext[64] || LE64(16) || LE64(64)
```

All wide RTL ports use byte-lane packing: protocol byte `i` is in bits
`[8*i +: 8]`. This keeps RFC little-endian words unambiguous.

## 64-session indexed request convention

The board-facing top uses one request channel and a 6-bit slot number. The PS
selects a ready connection, writes its packet and slot through AXI-Lite, and
waits for the shared engine response. Session keys, nonce prefixes and TX/RX
counters remain in a 1,536 x 32-bit PL BRAM table. The 64-session table maps to
two RAMB36E1 primitives; the 32-session parameter maps to one.

The legacy four-port arbiter below remains for regression comparison.

Request port `i` addresses session-table slot `i`. The requester holds
`req_valid_i[i]` and all of its flattened request fields until
`req_ready_o[i]` is observed. Responses are held in the corresponding slot
until `rsp_ready_i[i]` is asserted.

Session configuration resets both directional counters to zero. Encryption
uses and then increments the stored TX counter. Decryption accepts only the
current expected RX counter and increments it only after a valid Poly1305 tag.
This strict in-order rule is suitable for the first demo; a UDP deployment
that permits packet reordering should later replace it with a replay window.

## Implementation note

ChaCha20 evaluates one complete column or diagonal round per cycle using four
parallel quarter-round datapaths. Poly1305 uses five radix-2^26 limbs and
reuses one 28x29-bit multiplier across 25 schoolbook products per 16-byte
block. This favors low DSP use over Poly1305 latency and leaves DSP capacity
for ML-KEM.

The integrated AXI-Lite top accepts the complete ML-KEM-512 secret key and
ciphertext and automatically installs a valid Decaps result into the selected
AEAD session slot. Stages 6 and 7 are functionally complete and regression-
tested. The original top is retained as a simple golden architecture. The
preferred shared-Keccak top reduces synthesized primitive LUTs from 123,731 to
34,338 and is within the XC7Z020 capacity. See `IMPLEMENTATION_STATUS.md`.
The board-facing production candidate is
`mlkem_secure_channel_complete_axi_top`.
